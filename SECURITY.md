# Security Policy

## Supported Versions

This repository does not currently publish formal, versioned releases. Security fixes are therefore applied to the latest maintained source in the default `main` branch. Older snapshots, forks, and unmaintained branches are not guaranteed to receive security updates.

| Project version | Security support |
| --- | --- |
| Latest maintained source on `main` | Supported |
| Older snapshots and unmaintained branches | Not guaranteed |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues, discussions, pull requests, or public comments.**

Use GitHub's **Private vulnerability reporting** feature for this repository (open the repository's **Security** tab and choose **Report a vulnerability**) if it is enabled.

If private vulnerability reporting is unavailable, contact the repository maintainer privately through their GitHub profile:
https://github.com/amirjavanmard00-netizen

When reporting, include as much of the following information as possible:

- A clear description of the vulnerability and its potential impact.
- The affected file, endpoint, component, or configuration.
- Reproduction steps or a proof of concept that does not expose real user data.
- Any suggested mitigation, if known.

## Response and Disclosure

The maintainer will review reports and acknowledge them as soon as practicable. The reporter will be updated when the issue is confirmed, declined, or requires more information. Response and remediation times depend on severity, reproducibility, and the effort required; no fixed service-level timeframe is currently guaranteed.

Please allow the maintainer reasonable time to investigate and prepare a fix before sharing vulnerability details publicly. Do not include passwords, access tokens, API keys, Supabase service-role keys, database credentials, or personal data in a report unless a secure channel and a clear need have been established.

## Scope

This policy covers security issues in the NIOPDC media monitoring application and its maintained repository code. It does not authorize testing against production systems, third-party services, or infrastructure that you do not own or have explicit permission to assess.
